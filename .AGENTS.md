## 🎯 Key Technical Decisions

1. **No Build Tools:** Vanilla JS eliminates build complexity
2. **PocketBase:** Single binary backend simplifies deployment
3. **SQLite:** Embedded database requires no separate DB server
4. **Mobile-First:** Responsive design prioritizes mobile experience
5. **Dual User Types:** System supports both experts and clients with type-based profile creation
6. **Status Workflows:** 
   - Experts: pending → approved → active
   - Leads: New → Reviewing → Qualified → Proposal → Won/Lost

## 🔧 Technical Implementation Details

### Authentication Flow
1. User registers with email/password and user type selection
2. PocketBase creates user record in `users` collection
3. System auto-creates associated profile:
   - Freelancer → `experts` collection (status: pending)
   - Client → `clients` collection
4. User is auto-logged in and redirected to dashboard
5. JWT token stored in localStorage via PocketBase authStore

### Data Display Pattern
1. JavaScript fetches data from PocketBase API on page load
2. Filters applied (e.g., only published projects, only approved experts)
3. Data rendered to DOM using template literals
4. Images served via PocketBase file URL helper
5. Fallbacks for missing data (placeholders, default messages)

### Form Submission Pattern
1. Event listener on form submit
2. Prevent default form behavior
3. Gather form data into JavaScript object
4. Validate client-side (required fields, format)
5. Submit to PocketBase collection via API
6. Handle success/error responses
7. Display user feedback message
8. Reset form on success

## 🚧 Known Limitations & Technical Debt

1. **Hardcoded API URL:** PocketBase URL is `http://127.0.0.1:8090` in all JS files (needs environment variable)
2. **No Client-Side Routing:** Each page is separate HTML file (no SPA router)
3. **Limited Error Handling:** Basic try/catch, needs improvement
4. **No Loading States:** Forms should show loading during submission
5. **Duplicate Code:** PocketBase initialization repeated in each JS file
6. **No Input Sanitization:** Relies entirely on PocketBase validation
7. **No Rate Limiting:** Forms can be spammed
8. **No Spam Protection:** No CAPTCHA or honeypot implemented
9. **Inline Styles:** Some styling still in HTML, needs extraction to CSS
10. **Emoji Icons:** Service cards use emoji instead of proper icon system

## 💡 Recommendations for Future Agents

### When Adding Features:
1. **Check PRD.md first** - Ensure feature aligns with product requirements
2. **Review ARCHITECTURE.md** - Understand data model and API patterns
3. **Follow patterns in existing code** - Maintain consistency
4. **Update TODO.md** - Track progress on task list
5. **Test in multiple browsers** - Chrome, Firefox, Safari minimum

### Code Patterns to Follow:
```javascript
// 1. PocketBase initialization
const pb = new PocketBase('http://127.0.0.1:8090');

// 2. Fetching data with filters
const records = await pb.collection('experts').getList(1, 6, {
    sort: '-created',
    filter: 'status = "approved" && profile_public = true'
});

// 3. Creating records
const data = { /* form data */ };
await pb.collection('leads').create(data);

// 4. Error handling
try {
    await pb.collection('name').create(data);
    showMessage('Success!', 'success');
} catch (error) {
    console.error('Error:', error);
    showMessage('Error: ' + error.message, 'error');
}
```

### Architecture Principles:
- **Keep it simple:** No unnecessary frameworks or libraries
- **Mobile-first:** Design for mobile, enhance for desktop
- **Progressive enhancement:** Basic functionality works without JS
- **Security by default:** Validate all inputs, sanitize outputs
- **Performance matters:** Optimize images, minimize requests

### Testing Checklist:
- [ ] Works without JavaScript (forms use native HTML validation)
- [ ] Mobile responsive (test at 375px, 768px, 1920px)
- [ ] Cross-browser compatible
- [ ] Keyboard accessible
- [ ] Error states handled gracefully
- [ ] Loading states shown for async operations
